# Koppa post-build integrity example

This example builds Koppa 0.1.1, records the wheel and source archive, and checks their bytes with the existing Koppa `FunctionToken`, `seal`, `verify`, and `fixed_point_digest` operations.

**Scope:** artifact identity and byte-level integrity. This example does **not** yet verify transitive dependency identities, authenticate build attestations, establish builder trust, or implement enterprise deployment tracing. Those remain future integration work.

## Run locally

From the repository root, with Python 3.11:

```sh
python -m pip install build
python -m pip install ./koppa-0.1.1
python -m unittest discover -s koppa-0.1.1/tests -p "test_*.py" -v
python -m build --outdir dist koppa-0.1.1
python examples/supply_chain_integrity/koppa_integrity.py candidate --dir dist --output evidence/candidate-manifest.json
python examples/supply_chain_integrity/koppa_integrity.py verify --dir dist --manifest evidence/candidate-manifest.json --evidence evidence/candidate-check.json
```

The candidate command writes a JSON manifest with artifact filenames, sizes, raw SHA-256 digests, Koppa function tokens, and handle-framed digests. The verifier compares bytes against this manifest and returns a failing exit code for mismatches.

## Approval boundary

A manifest generated by the same job that generates its artifacts is **not** an independently approved reference. The default result is explicitly `CANDIDATE_INTEGRITY_CHECK_ONLY`: useful to exercise the implementation, but not a supply-chain security approval.

For a separate approval process, retain the manifest outside the build's write-access boundary and supply its expected SHA-256 digest from an independently trusted source:

```sh
python examples/supply_chain_integrity/koppa_integrity.py verify --dir dist --manifest approved-manifest.json --expected-manifest-sha256 <approved-64-character-sha256> --evidence evidence/approved-check.json
```

A pinned manifest authenticates the **expected artifact bytes** only to the extent the reference digest was independently approved and protected. Build provenance, dependencies, and signer identity require additional controls.

## CI

`.github/workflows/example-integrity.yml` runs the existing tests, builds both distributions, and uploads the unapproved candidate files and evidence. It does **not** deploy, merge, sign, or publish anything.

This is the first running example for the planned language-independent verification contract. Cucumber and Rust adapters are intentionally deferred.
